# delta-consumer
Extendable consumer service to sync data from external sources based on diff files generated by a producer like [delta-producer-json-diff-file-publisher](https://github.com/kanselarij-vlaanderen/delta-producer-json-diff-file-publisher).

## Getting started

Add the following to your `docker-compose.yml`:

```yaml
services:
  delta-consumer:
    image: kanselarij/delta-consumer:0.1.1
    environment:
      ALLOW_MU_AUTH_SUDO: "true"
      DCR_SYNC_BASE_URL: "https://kaleidos.vlaanderen.be"
      DCR_SECRET_KEY: "my-secret-key"
      DCR_SERVICE_NAME: "mirror-delta-consumer"
      DCR_DELTA_SYNC_JOB_OPERATION: "http://delta-consumer.services.semantic.works/id/JobOperation/DeltaFileSyncing"
      DCR_JOB_CREATOR_URI: "http://delta-consumer.services.semantic.works/me"
      DCR_START_FROM_DELTA_TIMESTAMP: "2025-08-29T15:48:00Z"
      DCR_CRON_PATTERN_DELTA_SYNC: "*/15 * * * * *"
    volumes:
      - ./data/files:/share
      - ./data/delta-files:/delta-files
```

The `DCR_SECRET_KEY` must be the same as the `KEY` configured at the producer side.

The values of `DCR_SERVICE_NAME`, `DCR_DELTA_SYNC_JOB_OPERATION` and `DCR_JOB_CREATOR_URI` should be unique in the application stack to distinguish the generator jobs and errors from the ones generated by other services.

## Discussion
### Why a fork of lblod/delta-consumer
This repository is a fork of [lblod/delta-consumer](https://github.com/lblod/delta-consumer). In order to make the consumer service more extendable/configurable, an experimental API to map and dispatch triples was added to this service. Ideally, this API will be merged back and used in the [lblod/delta-consumer](https://github.com/lblod/delta-consumer) but chances are high this will never happen in practice. 

The initial sync part of this service is not used by Kaleidos and therefore not actively maintained in this fork. Same reasoning holds for the old dispatcher API in the `./triples-dispatching` folder.

## Reference
### Data flow
#### Initial sync
Finds the latest `dcat:Dataset` a sync point to ingest. Once done, it proceeds in delta-sync mode.

See also [delta-producer-dump-file-publisher](https://github.com/lblod/delta-producer-dump-file-publisher).

#### Delta-sync
At regular intervals, the service will schedule a sync task. Execution of a task consists of the following steps:

1. Retrieve the timestamp to start the sync from
2. Query the producer service for all diff files since that specific timestamp
3. Download the content of each diff file
4. Process each diff file in order

During the processing of a diff file, the insert and delete changesets are processed. The user can configure transformations at 2 stages during the ingest pipeline:
1. A changeset transformer after downloading the diff file from the producer
2. A triple transformer before handling a changeset

In the end a dispatcher determines how triples from the diff file are dispatched at the consumer side. The dispatcher's behaviour can also be configured.

###### Changeset transformer
Mounted in `./config/changeset-transformer.ts`

Exports a function that is called on each changeset as received from the producer.

Input: `ChangeSet`

Output: `ChangeSet`

###### Triple transformer
Mounted in `./config/transformer.ts`

Exports a function that is called on each quad as received from the producer.

Input: `Quad`

Output: `Quad`

###### Dispatcher
Mounted in `./config/dispatch.ts`

Exports an async function that is called on each diff file (after transformations). Determines how triples are dispatched in the triplestore at the consumer side. May also add additional enrichments/behaviours like for example [downloading share files](https://github.com/redpencilio/file-share-sync-service).

Input: `ChangeSet[]`

Output: `Promise<void>`

### Configuration
#### Environment variables
Variables prefixed with `DCR_` belong to the core. `DCR` could be an abbreviation for `delta-consumer`.

The following environment variables are required:

- `DCR_SYNC_BASE_URL`: Base URL of the stack hosting the producer API [REQUIRED]
- `DCR_JOB_CREATOR_URI`: URL of the creator of the sync jobs [REQUIRED]
- `DCR_SERVICE_NAME`: unique name for the service in the stack. Used for error logging. [REQUIRED]
- `DCR_DELTA_SYNC_JOB_OPERATION`: Job operation of the delta sync job, used to describe the created jobs [REQUIRED]

The following environment variables are optional:
- `DCR_SYNC_FILES_PATH (default: /sync/files)`: relative path to the endpoint to retrieve the meta-data from the diff-files. Note: often, you will need to change this one.
- `DCR_DOWNLOAD_FILES_PATH (default: /files/:id/download)`: relative path to the endpoint to download a diff file
  from. `: id` will be replaced with the UUID of the file.
- `DCR_SYNC_FILESHARE_PATH (default '/fileshare)` : relative path to the endpoint to download share links
- `DCR_CRON_PATTERN_DELTA_SYNC (default: 0 * * * * *)`: cron pattern at which the consumer needs to sync data automatically.
- `DCR_START_FROM_DELTA_TIMESTAMP (ISO DateTime)`: timestamp to start sync data from (e.g. "2020-07-05T13:57:36.344Z") Only required when if initial ingest hasn't run. This value will be ignored if a ingest job already exists in the triplestore.
- `DCR_DISABLE_DELTA_INGEST (default: false)`: flag to disable data ingestion, for example, while initializing the sync
- `DCR_KEEP_DELTA_FILES (default: false)`: if you want to keep the downloaded delta-files (ease of troubleshooting)
- `DCR_DISABLE_INITIAL_SYNC (default: false)`: flag to disable initial sync
- `DCR_WAIT_FOR_INITIAL_SYNC (default: true)`: flag to not wait for initial ingestion (meant for debugging)
- `DCR_SYNC_DATASET_SUBJECT`: subject used when fetching the dataset (only required if initial sync is enabled)
- `DCR_INITIAL_SYNC_JOB_OPERATION`: Job operation of the initial sync job, used to describe the created jobs (only required if initial sync is enabled)

- `TARGET_GRAPH (default: none)`: graph in which to write the triples ingested by the delta sync
- `BATCH_SIZE (default: 50)`: Size of the batches of triples to ingest in the database
